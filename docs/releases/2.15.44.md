# Zai++ 2.15.44

> 内容脚本**启动链的编排**从 `main()` 里抽成可注入的模块，配套把一整族
> 「按名字找源码」的接线断言换成**行为测试**。功能行为不变。

## 变更

- **启动链的编排搬进 `core/zai/capability-install.ts`** ——
  `installZaiCapabilities(deps)` / `syncRuntimeStateBeforeUse` /
  `disposeZaiCapabilities` / `installZaiSessionWatch` / `notifyZaiSessionChange`
  五个函数，依赖全部由调用方注入，**本模块不 import 任何站点模块**。
  顺序与「哪几处刻意不 `await`」都逐条写在了注释里（那是契约的一部分）。
  `entrypoints/zai.content.ts` 的 `main()` 净减约 40 行。
- **斜杠补全的接线搬进 `core/ui/skill-popup-wiring.ts`** ——
  技能清单 → 候选的过滤与投影、以及三个注入原语的组装；
  原语**原样透传**（不做包装），调用方传什么就是什么。

## 为什么要动这一处

「这几处安装有没有真的接上」此前只能靠**读源码做 AST 断言**去守，而那种断言
只能问「源码里有没有出现这个名字」、问不出「它到底跑没跑到」。实测被下面这些
写法逐一绕过（每一种都 `tsc` 干净、全量用例全绿）：把调用挪进死函数 / 死类 /
死箭头；在目标函数里用 `const`、解构、`catch` 参数、形参重新绑定同名标识符；
把真身改名再在文件末尾补一个同名函数靠**声明提升**接管调用点；把 import 换成
同名 stub；在同名可达函数体内塞一个**诱饵**同名函数。

编排搬出来之后，测试可以**真的调它**并传桩依赖 —— 判据从「源码里有没有这个名字」
变成「**调了它之后，桩有没有被调**」，上面那一整族在结构上不再成立。

## 内部

- **接线守卫 22 条 → 7 条**，其余换成 `tests/zai-capability-install.test.ts`
  的 33 条行为测试（每个安装恰好一次、顺序、不被 await 的那几处、
  订阅回调接到面板处理、**每个监听源触发时两个消费者都被调到**）。
- 保留在 AST 层的只有三类：全局**孤儿检测**（没有正向行为可测）、
  工具面板的四个投递点、`REQUEST_TERMINAL` 的收尾（依赖面太大，行为化不划算）。
- 顺带删掉了 `isCompatible` 里一条**恒等冗余**的判据（原实现等价于
  `if (X && Y) return true; return Y;`，对任意输入返回值相同）。
