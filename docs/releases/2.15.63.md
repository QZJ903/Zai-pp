# Zai++ 2.15.63

> 本版是**浏览器控制与标签保活**（U16）的审计修复，外加两批附带工作：
> 主世界 import 边界的三处盲区、续跑 prompt 的快照去重。
> 没有新增能力，重点是让几处「坏了不报错」的地方变成看得见。

## 一、浏览器控制

**attach 半途失败不再留下「假连接」。** `attach` 原来先把内部绑定置位、再发五条
CDP 域启用命令，任一条失败就抛错但绑定不回滚 —— 于是下一次 `attach` 同一条标签，
第一行「已经在同一条就 return」直接早退，**一条命令都不重发**。那几个域永远没启用，
而状态显示「已连接」。现在初始化失败会把绑定收回去，下次重连能真的重来一遍。

**后台标签上点击不再永久挂住。** 元素不可见时会先滚动、再等一帧
（`requestAnimationFrame`），而 Chrome **从不给后台标签调 rAF**（自 2011 年起，
官方文档明写）。而浏览器控制的目标标签常态就在后台 ⇒ 那个等待永不返回，整条工具
调用卡死、内容脚本的执行计数永不归零、续跑循环停在 running。现在不等那一帧，
并且把滚动方式改成同步的 `instant`（`auto` 会尊重页面的 `scroll-behavior: smooth`，
滚动变异步、同步读位置仍是旧的）。

**动作声明的时间与结果上限真的生效了。** 18 个浏览器工具都写了 `timeoutMs`
（等待类 65 秒、快照 15 秒、其余 10 秒）和 `maxResultBytes`，而本地工具链上
**没有任何地方读它们** —— 唯一读取点在 MCP 那条链。两条一起接上：
`chrome.debugger.sendCommand` 本身没有超时，一条挂住的命令能让整次调用永不返回；
结果超预算时只裁 `detail`（`output` 是结构化数据，裁了会让「保存」这类按钮消失）。

**关标签的保护判据修对了。** 原来判的是「这条标签有没有被保活挂着」，而那个集合
只装「真在后台且开关开着」的标签 ⇒ **开关关着（默认值）或标签在前台时恒不生效**，
这两格恰恰最常见。现在改成直接问页面「有没有续跑在跑」。

**关标签不再覆盖别人的目标切换。** 尾部原本用开函数时读的旧快照判断要不要清空
target，中间隔着一次 `await tabs.remove` —— 这期间侧边栏改的 target 会被覆盖成
null。判断挪到写盘那一刻。

**填表单对现代前端生效了。** 原来直接赋 `value`，React 的受控组件看不到变化
（填完看着对，页面下一次重渲染又变回空）。改成走原型上的原生 setter。

**其余四条**：换控制目标后清掉旧快照的 uid 映射（否则会拿上一条标签的节点 id
去新标签上解析）；`browser_key` 的字符键改用会产字符的事件类型、非 ASCII 不再
拼假的键码；`browser_attach_file` 拒绝空文件数组（原来会静默清空文件选择）；
两个设置项加上串行队列，并发保存不再互相覆盖。

## 二、标签保活

**快照与截断**：快照文本预算改按真 UTF-8 字节判（原来按 UTF-16 码元判，中文会
超出一倍多），两个预算的截断点对齐（避免「看不见却能点」），上界从 80000 收到
24000，滑块的每一格现在都有意义。

## 三、续跑 prompt

**同一份快照不再出现两次。** 动作结果里 `detail` 与 `output.snapshot.text` 各带
一份全文，进模型时又各自被裁 —— 载荷翻倍，裁下来的还是同一段开头。现在只留
`detail` 一份。

**只有最新一份快照保留正文。** 快照的 uid 是「第 N 个节点」的编号，而每次拍新快照
都会清空映射 ⇒ 旧快照的 uid 已经失效。实测：模型照旧快照的 `e1`（「提交订单」）
去点，实际点到的是另一个元素，**零报错**。现在更早的快照压缩成摘要，不保留会
误导的旧坐标。4 份快照的场景从 96 KB 降到 25 KB。

**完整条目的摘要也有了上界**（原来只有压缩条目有）。

## 四、主世界 import 守卫

主世界脚本跑在页面里，没有 `chrome` 对象、也没有扩展的 i18n 资源。这条约束原来
只写在注释里。上一版加了守卫，本版补掉三处盲区：路径别名（`@/` `~/`）原来被
静默跳过，含 `chrome?.` / `chrome[…]` 的写法漏判，以及「模板串里的 `//` 会把其后
整行当注释剥掉」导致漏报。

## 五、校验

`tsc` 0 错 / **186 文件 2305 测试全绿** / `verify:i18n` 通过 / chrome + edge 双构建通过。

## ⚠️ 升级须知

1. **重载扩展** —— service worker 常驻，改磁盘不会重载它；重建后侧边栏若开着也要刷新。
2. **本版不涉及 Native Host**，不用重装。
3. **真机验收还剩五项**：保活那两条 CDP 命令是否真的解除后台节流、`browser_fill`
   在 Svelte / Vue 页面上是否同样有效、中右键点击是否需要鼠标按键位掩码、
   `browser_wait_for` 的循环精度、以及 `chrome.tabs.get(-1)` 的错误串措辞。
