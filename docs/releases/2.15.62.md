# Zai++ 2.15.62

> 本版把四批审计修复一次性收口，并修掉一批「坏了不报错」的静默缺陷。
> 没有新增能力；重点是让失败变得可见、让上限不再互相打架。

## 一、外壳进程（Shell Native Host）

⚠️ **本版的 host 改动必须重装才生效** —— `native/` 会被拷进安装目录，
重建扩展不会更新它。

```
npm run shell:install -- install --browser <browser> --extension-id <id>
```

**进程不再带异常退出。** 原来 `sessionProvider.shutdown()` 只挂在正常结束与
promise 拒绝两处，而 spawn 失败、stdout 写失败、非法帧三条路都绕开它 ——
进程死了，已开的持久会话 shell 变成没人管的孤儿。现在加了 `process.on('exit')`
兜底，三条路都会先回收会话。`shell_session_begin` 的 `shell` / `cwd` 都是模型可控
入参，传错一个原来会让整个 host 退出。

**输出上限按字节算了。** 原来按字节判、按字符截，中文会被放过三倍、emoji 四倍；
而且跨 64 KiB 管道边界的中文字符会被切成两半、各解成 U+FFFD。现在用
`StringDecoder` 逐块续接，两条截断分支都按字节走。

**超 1 MiB 的响应改成硬拒。** 原来只打一行 warning 照发，Chrome 那边直接断连。
现在回一条可读错误，host 不受影响。

**技能预览按最终帧大小裁剪。** `MAX_LOCAL_SKILLS(80) × MAX_LOCAL_SKILL_BYTES(120KB)`
原来完全不受总预算约束，实测能拼出 9 MB 的响应。现在量序列化后的真实字节，
超了从尾部丢技能并给警告；显式选择超预算时明确报错让分批导入；单技能超预算才截断。

**另外三条小的**：先按 `selectedPaths` 过滤再截断（显式选中的第 81+ 个不再被吞）；
一个读不出来的 SKILL.md 不再拖垮整次预览；`local_file_read` 的 `start` 越界报错
而不是返回空串判成功。

**安装器**：重装时清掉自己的旧模块（改过名的文件原来会一直留着）；
`uninstall` 先看还有没有别的浏览器在用共享 runtime，有就保留。

## 二、MCP 与工具链

**`local_file_write` 的信封检查补了个洞。** 原来 content 在 512 KB–900 KB 之间会
直接跳过信封测量，而 JSON 转义会膨胀（引号翻倍、控制字符六倍）—— 一份 900 KB 的
JSON 内容能拼出 1.07 MB 的帧，host 直接退出。现在一律测量真实信封，撞上限时
文案点名 `append=true` 分块写。

**MCP 错误不再把工具历史弄坏。** JSON-RPC error 不带 `data` 时，代码写的是
`data: undefined` —— 键还在、值是 `undefined`，而工具历史的 codec 要求合法 JSON
⇒ 整条记录判非法 ⇒ 用户看到「执行失败」，而实际是历史存不进去、工具早就跑完了。
现在只在真的有 `data` 时才放这个键。

## 三、持久化

**journal 恢复分两档。** 解析/校验失败丢弃并上报后继续，回滚执行失败保留并阻塞。
原来只有一档 —— 一份读不出来的 journal 会让恢复步骤挡住之后**每一次**加锁操作
（**含只读入口**），删技能、导入、删预设全部失败，而且 journal 永远清不掉。

**技能名判重扩到 builtin + remote。** 名字是身份：`/name` 激活只按名字取列表第一条，
重名时后面那条永远调不到。slug 化从五处手抄合成 `core/skill/slug.ts`。

**删掉云同步的落地链。** 上传半在 2.14.53 删掉之后，`coordinator.apply` 与
`stageSyncLocalApply` 一直没有生产消费者。恢复链保持完整。

## 四、站点适配与提示词

**`/chats/new` 的解析与重写共用同一个容器查找。** 原来解析容忍三种形状、重写只认
第一种，收到兜底形状时首条消息静默不增广。

**标签页解析纳入 deadline 与 abort。** 原来 `resolveDomTab` 的六处 await 全在约束
之外，挂住时 `startTask` 永不完结、租约永久留在内存里。

**模型清单请求加上界**，超时值用独立常量。

**两张表改成 mapped type**，把「每一行的身份字段必须等于它自己的键」编码进类型。

**活跃站按「用户正在看的那个页面所属的站」重建** —— 读侧改成实时查最后聚焦窗口的
当前标签页，查不到才读记录；写侧加载时判可见性。

**提示词**：`systemPromptEnabled=false` 时不再单独补沙箱段（那段正文引用的工具清单
同样在开关里）；shell 工具名清单改从本轮目录派生；能力判定改按
`provider.transport === native_messaging`；`signature_prompt` 直接写用户原文。

**adaptive 字节预算改真渲染量字节** —— 原估算器系统性高估 2–3 倍，
默认 24000 预算下只放出 13/40 个工具，改后 34/40。

## 五、记忆与用量

**记忆访问计数不再恒空。** `TOUCH_MEMORIES` 一直发空 ids，`accessCount` /
`lastAccessedAt` 从未更新 —— 而它们是 `decayScore` 与 `archiveStaleMemories`
（90 天未访问且次数 < 3 就删）的唯一输入。后果是检索退化成纯关键词匹配，
且所有没 pin 的记忆会在创建 90 天后被每次启动静默删掉。

**记忆表单补 `key`**，编辑 A 期间点 B 的编辑不会把内容串进 B 的 id。

**用量窗口按日历日推进** —— DST 前拨日当地一天 23 小时，减 24 小时会落回前一天，
那个日历日整天从窗口消失。

**cron 频率判据改按固定锚点**，不再依赖参考点；新增「相邻命中超一年」的创建期拒绝。

## 六、校验

`tsc` 0 错 / **181 文件 2170 测试全绿** / `smoke:shell` 17 项全过 /
`verify:i18n` + `verify:automation` + `prompt:freeze` 全过 / chrome + edge 双构建通过。

## ⚠️ 升级须知

1. **重装 Shell Native Host**（见开头）—— 不重装的话第一节全部不生效。
2. **重载扩展** —— service worker 常驻，改磁盘不会重载它；
   重建后侧边栏若开着也要刷新（旧 chunk 哈希还在内存里）。
3. **真机验收还有四项没做**：Windows 上 `[Environment]::Exit(2)` 的 `error.code`
   是不是 2、Chrome 对超限帧的处理、`powershell -Command -` 的持久会话行为、
   Windows PATH 探测的耗时。前两项影响的是「修法对不对」，后两项影响的是
   「Windows 上能不能用」。
