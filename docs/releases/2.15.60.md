# Zai++ 2.15.60

> 本版继续修「刷新后界面不对」这一类问题：工具面板不再叠两块、不再永久展开，
> 另外补了几处会让扩展在后台静默失效的连接问题。
>
> ⚠️ **2.15.58–60 在收口同一件事**：标签保活（防后台节流）不该让用户看到
> 「Zai++ started debugging this browser」横幅。58 改成按标签各保一条，59 试了「按可见性挂」，
> 60 修正了它的判据（**页面自己的 `document.hidden` 会被保活自己改写**），并把挂载窗口缩到
> **只有发送那几秒**。

## 修复：同一条回答里出现两个工具面板

刷新会话后，同一条回答下面偶尔会上下叠出两个「已调用工具（N 次）」，**上面那个点不开详情**
（行里只有工具名和「已执行」），下面那个才有真实结果。

成因是工具记录的「历史」与「本地执行记录」是两条独立的数据来源，它们本该合成一条；
没合成时两边各自画了一块。现在**同一条回答里只会有一块面板**，后到的那条数据会并进已有的块，
真实结果也不会被后来那份「只有工具名」的数据覆盖掉。

## 修复：面板刷新后又自己展开

带 Skill 草稿 / 记忆导入预览的那一块，以前**刷新、切走再切回来都会重新展开**
（跑几轮就是几块全展开）。现在统一成「**只展开一次**」：那一轮在跑的时候展开，
轮次结束与刷新之后都收起。展开块之后，「保存」「导入」按钮仍在。

## 修复：续跑在后台标签里会被浏览器节流掐断

续跑与自动化的发送链跑在页面里，靠一串 80–150 毫秒的短轮询串起来。浏览器控制一旦打开一个前台
标签，z.ai 就被挤到后台，Chrome 会把定时器降到每秒一次、隐藏久了直接冻结，于是那些轮询全部超时，
任务被判定成「没发出去」并静默收尾 —— 你看到的是「只打开了网页、没有后续操作」。

现在续跑期间会给 z.ai 标签开一条独立的调试会话，让它自报前台且不被冻结，**窗口可以最小化**。
⚠️ **代价**：挂上调试会话时 Chrome 会在所有窗口顶部显示「Zai++ started debugging this browser」；
点它的 Cancel 会掐掉扩展的全部调试会话（包括浏览器控制）。这是浏览器给用户的知情权，拦不住。
⚠️ **所以它只在真正需要时才挂**：只包住发送那几秒、且只有标签确实在后台时才挂
（详见下面「横幅」那条）。

## 修复：z.ai 标签不能再被浏览器控制当作目标

同一条标签、同一个扩展，第二次挂调试会话必被浏览器拒绝 —— 而续跑保活正挂在 z.ai 标签上。
两边代价不对称（保活挂了是零日志的静默失败，浏览器控制少一个目标只是少一个可操作对象），
所以让浏览器控制退一步：

- 浏览器控制页里 z.ai 那行会**置灰**，并给出中文原因；
- 让它导航到 z.ai 会被**直接拒绝**，标签 URL 不变（前进 / 后退两个入口同样拦）；
- 动作把标签带到不可控状态之后，扩展会**主动解除**那条调试会话，不会留在 z.ai 上挡住续跑；
- **正在被续跑保活的那条标签不许被关闭**（关掉等于当场掐断那一轮）。

## 修复：失败信息不再是裸错误码

侧边栏里原本会直接显示 `busy`、`automation_not_found` 这类内部错误码，现在统一变成
「操作失败（busy）」这种人话；工具详情里的 `error:` 段只留一句可读的原因，不再把整个错误对象
序列化出来；技能保存失败时按钮显示「保存失败」而不是 `skill_exists`。记忆总数读取失败显示
`—` 而不是 `0`（后者会让人以为数据没了）。

## 修复：几处会让错误面板亮红、或让连接状态说谎的缺陷

- 三处未捕获的 promise rejection（HTML 挑战页推进、工具轮次收尾、续跑三个「没发出去」的出口）已补齐。
- 浏览器控制的「断开」在失败时不再假装成功 —— 以前会显示「已断开」而调试会话其实还挂着，
  且那个假状态**只有重启浏览器才能恢复**。
- 续跑保活撞上「同一条标签上已有本扩展的调试会话」时会自己放掉旧会话再重试一次，
  不再静默放弃（放弃的表现是被挤到后台之后任务卡住）。

## 修复：「Zai++ started debugging this browser」横幅

模型一调工具（shell / MCP / 浏览器工具都算），扩展就会给 z.ai 标签挂一条调试会话来防后台节流 ——
而**只要挂了 debugger，Chrome 就会在所有窗口顶部画那条横幅**，即便当前页面在前台、根本不需要防节流。
看起来就像「莫名其妙弹了个东西」。

三条一起改：

1. **只在「发送链」那几秒挂** —— 真正会被节流掐断的只有发送时那几条 80–150 毫秒的短轮询；
   等响应是网络事件驱动的、不吃定时器。所以 `want` / `unwant` 只包住发送这一段（`finally` 兜底）。
2. **前台不挂** —— 判据是 `chrome.tabs.active` + `windows.focused`，**不是页面自己的
   `document.hidden`**：后者会被保活自己发的焦点模拟改成 false（页面自报前台），
   用它当判据会在挂/卸之间无限来回跳，横幅反复出现、保活还等于没起作用。
3. **页面刷新后清掉上一页的残留** —— 保活活在后台、按标签记，内容脚本是每页一份；
   页面一刷新，旧循环连同它的收尾一起消失，而后台那条会话还在 ⇒ 横幅永久滞留。

## 修复：同时开两个自动化，后台那个的续跑会断

两个自动化同时跑时，协调器会给第二个任务新开一个 z.ai 标签并**把它激活**（首次加载需要前台
初始化），于是先前那个自动化标签被挤到后台 —— 而它正卡在发送链的 80–150 毫秒短轮询里。
保活本该救它，但保活当时**只保一条**：另一个标签一挂上就把它的会话顶掉，任一方收尾又会把
「当前那一条」解掉 ⇒ 两边轮流抢，**谁在等响应那段长窗口没抢到，谁就被浏览器节流、静默收尾**。

现在保活**按标签各保一条**：同一扩展可以同时挂多个标签（横幅仍是每扩展一条，不会变多），
停止保活也只会停自己那条。两个自动化可以真正同时跑。

## 修复：草稿面板展开后立刻收起（同版本内补）

上一版把「面板只展开一次」实现成了「轮次一结束就收起」，于是 Skill 草稿那块刚展开就没了。
现在按正确口径：**只要那块里还有没点过的「保存 / 导入」按钮，轮次结束也保持展开**；
**刷新页面或切会话之后一律收起**（那时是从历史恢复的，不是刚才跑的那一轮）；
点过保存之后按钮换成「已保存」状态行，再重画就收起。

## 修复：浏览器控制工具的 XML 与面板一起显示

历史里的工具 XML 本应被剥掉、只留面板。剥除名单里漏了浏览器控制那 18 个工具名，
而那份动态名单在页面刚加载时还是空的 —— 所以 shell / memory / skill 的 XML 都剥掉了，
**唯独浏览器工具的留在正文里**。已补进静态基线，并给对账守卫加上这一组。

## 其他

- 提示词按「两条通道」重写：清单内的工具走 XML 标签、清单外的走原生 tool_call；模型把本地工具
  写进原生通道时会自动纠错一次。
- 一轮回答里执行过的工具收进一块可折叠列表。
- 聊天输入框里敲 `/` 弹出技能候选。
- 工具卡片改为中文人话说明 + 风险徽章（只读 / 写入 / 执行）。

## 验收

① **只出现一块面板**：跑一轮用了几次工具的回答，刷新会话十几次，
每次同一条回答下面**只有一块**「已调用工具」；展开能看到真实结果，不会退回只有「已执行」。

② **草稿面板该开的时候开着、刷新后收起**：
   - 让模型起草一个 Skill，那一轮**刚结束时块保持展开**，「保存」按钮直接可见（不该刚展开就收起）；
   - 点「保存」之后重画，按钮换成「已保存」，块可以收起；
   - 刷新页面或切走再回来，块是**收起**的（只剩块头），点开仍能看到按钮。

③ **两个自动化同时跑**：新建两个自动化任务、都设成马上跑一次（或者一个手动触发、一个按排期），
   让它们各自落到不同的 z.ai 标签上。**两个都应跑完**，不该出现「其中一个停在运行中 / 静默收尾」。
   ⚠️ 观察点：Chrome 顶部的「Zai++ started debugging this browser」横幅只应有一条（不会变成两条）。

④ **浏览器工具的 XML 不再露面**：让模型调用一次浏览器工具（例如 `browser_list_tabs`），
   **刷新页面**后助手正文里不应出现 `<browser_list_tabs>…</browser_list_tabs>` 这类原样文本，
  只应有工具面板。

⑤ **看不到调试横幅了**：模型调一次工具（比如让它读个文件），**页面停在 z.ai 上不动** ——
   Chrome 顶部**不应**出现「Zai++ started debugging this browser」。
   然后切到别的标签待几秒再切回来，横幅**最多闪一下**（发送那几秒）就该消失，不该反复出现。

⑥ **续跑不再被后台节流掐断**：让模型调用一个浏览器工具把 z.ai 挤到后台，任务应继续跑完；
中途按一次 F12 再关掉，任务仍能继续。

⑦ **z.ai 那行置灰**：浏览器控制页里 z.ai 标签显示为不可选 + 中文原因；让它导航到 z.ai 应被拒绝，
标签 URL 不变。

⑧ **侧边栏不再出现裸错误码**：制造一次失败，红条显示「操作失败（xxx）」而不是光秃秃的码。

⑨ **工具详情是人话**：失败工具的详情里 `error:` 段只有一句原因，没有 `{"code":…,"retryable":…}`。

⑩ **记忆总数**：读取失败时显示 `—`。
