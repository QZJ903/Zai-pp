# Zai++ 2.15.53

> 本版把**工具页整块删掉**（它只剩一张 Python 卡片，而那卡片做的三件事 MCP 页全都有），
> 顺带把**自动化搬回能力页**、在 MCP 页补上一条此前完全缺失的提示，并按代码评审收口了一批小问题。
>
> 前两版（2.15.51 / 2.15.52）的内容一并记在这里 —— 三版连着发，**升级到 2.15.53 就已包含全部改动**。

## 评审收口（2.15.53）

- **MCP 页「Shell Native Host」那一栏的折叠判据改对了** —— 上一版用「没有错就折叠」，
  把「已创建但未启用」「请先安装」这两档也一起折叠了，而那正是首次使用最该看见安装命令的时刻。
  现在改成「没有错**且**已就绪」才折叠。
- **「工具没返回」告警不再误报** —— 用户自己把「工具上限」调小时，列表被本地截断，
  以前会报「N 个工具没有返回……多半是 Native Host 版本旧了」（让人白装一遍）。
  现在只有实有数量没撞到上限时才报。
- **英文界面不再混入中文顿号** —— 缺失工具名的分隔符改走 i18n。
- **删掉一条从未被使用过的运行时命令** `REQUEST_HOST_PERMISSION` —— 它只在「host 权限是可选」
  的模型下才有意义（上游就是这样），而本项目把跨源权限声明成了必需，运行时无需请求；
  自项目建立起就没有任何代码发出过它。命令面 **96 → 95**。
- 命令清单文档里两处漏改的计数、三处过时注释、一个丢失的行尾换行一并修正。

## 删除

### 扩展自带的联网搜索（2.15.51）

`web_search` / `web_fetch` 两个工具连同 provider、描述符工厂、执行器整体删除；
侧边栏「工具」页的两个开关与「诊断搜索」一并去掉。
同理删掉三条运行时命令 `GET_WEB_TOOL_SETTINGS` / `SET_WEB_TOOL_SETTING` / `DIAGNOSE_WEB_SEARCH`
（命令面 **99 → 96**），以及「每轮把 `features.auto_web_search` / `features.web_search` 强制
写成 false」那条「关掉页面原生搜索」的链。

### 自动化任务里的「联网搜索」开关（2.15.51）

`AutomationPromptOptions.searchEnabled` 连字段一起删。
⚠️ **旧任务记录不受影响**：存储解码对未知字段原样带过，那条旧值会留着但不再起作用。

### bing 域名权限（2.15.51）

`*://cn.bing.com/*` / `*://www.bing.com/*` 从清单删除。⚠️ `http://*/*` / `https://*/*` **保留**
（MCP 自配端点与 GitHub skill 导入仍需要）。

### 整个「工具」页（2.15.52）

它只剩一张 **Python 解释器**卡片，而那张卡片做的三件事 —— 开关、创建 Shell、刷新工具 ——
**MCP 页的 Shell 服务里全都有**，且 MCP 页那份更完整（还带 Native Host 安装指引）。
唯一不可替代的是它对 `python_exec` 缺失的专门报错，而那条**已在 MCP 页补上**（见下）。

⇒ 删掉 `ToolsPage.tsx` 与 `useToolsPageController.ts`，能力页的「工具」标签一并去掉。

## 界面

- **能力页**：Skill / MCP / 浏览器 / **自动化**（自动化搬回来了）。
- **MCP 页**：Shell 服务那一栏新增一条提示（见下）。
- **自动化表单**：「固定会话」占满整行 —— **标题在行首**（原来「联网搜索」四个字的位置），
  **开关在行最右**（原来它自己的位置）。字段本身与保存逻辑都没变。

## 修复

### MCP 页看不到「Shell 连上了、但少返回了工具」

**症状**：Native Host 版本旧时会少发布几个工具。那时 `health.status` 是 `ready`、
`error` 为空 ⇒ MCP 页报「已连接，发现 N 个工具」，而工具列表里就是少几个、**一句话都不解释**。
用户只能猜「是不是坏了」。

**改法**：在 `ready` 那一档之前插一档「应有 − 实有」检查 —— 拿 `SHELL_TOOL_NAMES`（12 个）
减去实际返回的工具名，非空就列出来并提示「多半是 Native Host 版本旧了，重装并重启浏览器」。

⚠️ **判据用完整清单，不用给提示词看的裁剪版**（`EXPOSED_SHELL_TOOL_NAMES` 剔掉了
`local_skill_preview`，用它会把一个正常工具假报成缺失）。
⚠️ **这一档在「未找到 Native Host」等错误分支之后** —— host 根本没装时工具列表本来就是空的，
顺序反了会把「未找到 Native Host」显示成「12 个工具没有返回」。
⚠️ **那一栏的展开状态改成按 `isError` 判**（原来是「连上就折叠」）——
否则这条告警会躺在折叠区里，用户不展开就看不见。

## 保留不动

- **模型提示词里服务端沙箱的联网说明**（`Skill(command="web-search")` / web-reader 那段）——
  那是服务端自己的搜索，与扩展工具不是一回事。
- **老会话里残留的 `web_search` / `web_fetch` 工具块仍会被清理**（历史剥离基线里留着这两个名字）。
- **含这些工具的旧工具记录仍按「可续跑」处理**。

## 验收

① **能力页**：标签是 Skill / MCP / 浏览器 / **自动化** 四个，**没有「工具」**。

② **MCP 页**：点开 Shell 服务，工具列表能逐行勾选；「自动执行策略」开关与它下面的下拉都在。
   **不该**再出现任何「工具页」入口。

③ **自动化表单**：「固定会话」这一行的**标题在最左边**（原来「联网搜索」的位置）、
   **开关在最右边**（与它原来的位置一致）；表单其余字段位置不变。

④ **旧任务照常打开**：升级前就存在的自动化记录仍能显示、编辑、保存。

⑤ **Shell 服务那一栏**：正常时显示「已连接，发现 N 个工具」；
   **若你的 Native Host 是旧版**，会看到「已连接，但有 N 个工具没有返回：…」并点名是哪几个。

⑥ **Python 仍可用**：在 MCP 页展开 Shell → 发现工具 → 勾上 `python_exec`
   （以及你需要的 `shell_exec` 等），然后在对话里让模型执行一段 Python。
